界面作为**沙盒化模块**在 Label Studio 编辑器中运行。默认情况下，该沙盒**没有出站网络访问权限，也无法加载第三方代码**。这是一种有意的安全策略，您可以在界面需要时放宽此限制。

常见的使用场景小而具体：从您的 ML 后端获取预测结果、使用 `date-fns` 格式化日期、使用 `zod` 验证数据负载、从瓦片服务器拉取地图瓦片，或使用 `d3` 绘制图表。当您的界面需要外部 API 或第三方库时，可以通过以下三种方式之一来启用所需功能。

最常见的混淆点是：**"调用外部 API"和"使用外部包"是在不同的地方配置的。** 在错误的部分将主机加入允许列表不会产生任何效果。本页面将说明两者的区别。

## 三种方式一览

| 您想要…… | 示例 | 在哪里启用 |
|---|---|---|
| **从界面调用外部 HTTP 服务** | 通过 `fetch()` 调用您的 ML 后端、地理编码器、内部微服务、瓦片服务器 | **组织 > 设置 > 界面 → API 来源（API origins）** |
| **在运行时从 CDN 加载第三方包** | 通过 `<script>` 标签从 `cdn.jsdelivr.net` 拉取 `three.js` 或 `d3` | **组织 > 设置 > 界面 → 高级：外部脚本（Advanced: external scripts）** |
| **使用无需外部网络的第三方包** | 将 `three.js` *打包进*界面并发布 | 无需配置。代码是自包含的。 |

## 选择一种方式

- **通过 HTTP 调用服务？** → **API 来源（API origins）**（方式 1）。
- **需要第三方库且可以信任 CDN？** → **高级：外部脚本（Advanced: external scripts）**（方式 2）。
- **需要第三方库且无外部依赖/离线环境/严格安全要求？** → **本地打包**（方式 3）。*推荐默认方式。*

您也可以组合使用。例如，一个点云界面可以**本地打包 `three.js`**（方式 3），*同时*在 **API 来源（API origins）** 下**将您的瓦片/资源服务器加入允许列表**（方式 1），以便获取要渲染的数据。

!!! info 我能否使用第三方库？
    可以。界面源代码不能使用 `import`/`require`，因为每个界面是一个自包含模块，而不是 ES 模块。这是对**模块语法**的限制；第三方代码仍然可以使用。通过从允许列表中的 CDN 加载库（方式 2）或将其打包进界面（方式 3）来引入库。

## 方式 1：调用外部 API 或服务（API 来源）

当您的界面需要通过 `fetch`、`XHR` 或 `WebSocket` 与 HTTP 服务通信时使用此方式。例如：将选中的区域发送到 ML 后端进行推理、对地址进行地理编码或拉取地图瓦片。

1. 前往 **组织 > 设置 > 界面 → API 来源（API origins）**。
2. 添加精确的来源（协议**和**主机），例如 `https://api.example.com`。每个条目一个主机。
3. 保存。您界面中对该来源的 `fetch()` 调用现在可以成功执行。

| 规则 | 详情 |
|---|---|
| 格式 | 包含协议的完整来源（`https://主机`）。 |
| 通配符 | 不允许（不支持 `*` 或 `*.example.com`）。请明确列出每个主机。 |
| 您的 LS 服务器 | 始终自动允许。不要添加它；只列出第三方主机。 |
| 空列表 | **无出站网络。** 界面只能访问您的 Label Studio 服务器。 |

**API 来源（API origins）**仅管理**数据请求**。它**不会**允许您从该主机加载 `<script>`。如果您在此处添加包 CDN 期望加载库，不会产生任何效果（应使用方式 2）。

!!! info 示例
    要将自定义 ML 后端连接到界面，请在此处将后端的来源加入允许列表。这样界面就能向其发送区域数据负载并渲染预测结果。这里没有安装任何包；这是一个 API 调用。

## 方式 2：从 CDN 加载包（高级：外部脚本）

当您希望方便地在运行时直接从 CDN 拉取库，并且**完全信任该主机**时使用此方式。

1. 前往 **组织 > 设置 > 界面 → 高级：外部脚本（Advanced: external scripts）**。
2. 开启 **允许外部脚本/样式表（Allow external scripts / stylesheets）**。
3. 添加一个或多个脚本来源，例如 `https://cdn.jsdelivr.net`。
4. 在您的界面中，从该来源加载库（例如，注入 `<script>` 并使用其全局变量）。

| 规则 | 详情 |
|---|---|
| 协议 | 必须为 `https://`。拒绝 HTTP 来源。 |
| 格式 | 仅来源（不含路径、查询字符串、凭据或片段）。 |
| 通配符 | 不允许。 |
| 开关 | 除非复选框已开启，否则来源将被忽略。关闭开关会在保存时清除列表。 |

这是与 **API 来源（API origins）** 不同的设置。列在此处的主机可以向您的界面提供可执行代码；列在 **API 来源（API origins）** 下的主机不能，反之亦然。

!!! warning 警告
    从这些来源加载的脚本以界面的**全部权限**运行，可以读取界面正在渲染的任何任务数据。只添加您完全信任的主机。大多数组织应保持此部分禁用，并优先选择**方式 3**。

## 方式 3：本地打包（无需加入允许列表，无需网络）

**推荐用于锁定环境、本地部署或离线部署，以及任何不希望开放出站来源或信任 CDN 的团队。**

由于界面是**单个自包含模块**，第三方库可以存在于您的界面代码*内部*。该库成为您发布内容的一部分：无需 CDN、无需 `<script>` 标签、无需允许列表条目，标注时也无需出站网络。

**如何操作**

1. 获取一个**附加到变量的浏览器构建版本**：一个预构建的单文件 `dist`，或使用打包工具生成（例如，`esbuild --bundle --format=iife --global-name=MyLib`）。界面源代码会被编译但**不会**为您打包，因此请先将依赖解析到此单文件中。避免使用 **ES 模块**构建：不支持 `import`/`export` 语句。
2. 将该代码包含在您的界面源代码中，并通过库定义的变量/全局变量来引用它。**不要**在您自己的代码中使用 `import`/`require`。
3. 像往常一样验证、预览和发布（通过界面编辑器，或 `label-studio-sdk interface validate/preview/sync`）。该库会随发布的界面一起提供。

**哪些库适合这种方式**

- 纯计算和渲染库：日期/数字工具、验证库（如 `zod`）、图表/几何库以及浏览器内渲染器。
- 标准浏览器渲染 API：**沙盒中提供了 Canvas 和 WebGL**，因此像 `three.js` 这样的库可以在界面内渲染。（*iframe 功能*列表管理的是设备功能，如摄像头和麦克风，而非 2D/3D 渲染。）

**需要注意的限制**

- **使用 IIFE/全局构建。** 不支持 `import`/`export` 语句，依赖于顶层 `module.exports` 或 `require(...)` 的构建可能无法通过验证。您也不能在标注时 `require()` 一个 npm 包；请将依赖打包到文件中，而不是 require 它，并引用其定义的变量/全局变量。
- 该库必须在**沙盒内的浏览器中**运行：不能使用 Node.js API，无法访问父页面的 `window`/`document`，没有持久的 `localStorage`/`sessionStorage`，库自身执行的任何网络请求仍然受 **API 来源（API origins）**（方式 1）的约束。
- 打包后的代码会成为界面存储内容的一部分。没有固定的大小限制，但非常大的包会增加加载和解析时间，因此请留意这一点。

## 实践示例：渲染大规模点云

假设您需要审查 LiDAR 点云，并希望使用 `three.js` 来渲染它们。

- **离线/严格安全环境：** **本地打包 `three.js`**（方式 3）。无需任何允许列表；渲染器随界面一起发布。如果点云数据是从某个服务获取的，请在 **API 来源（API origins）**（方式 1）下添加该数据主机。
- **可接受 CDN：** 在 **高级：外部脚本（Advanced: external scripts）**（方式 2）下将 CDN 加入允许列表，并从那里加载 `three.js`。

点云**渲染**之所以可行，是因为沙盒中提供了 WebGL。真正的限制是**数据大小和性能**：无论库如何打包，非常大的点云都会对浏览器/WebGL 内存造成压力，因此请使用代表性数据进行测试，并根据需要进行降采样或分块。

!!! info
    目前已有大型第三方渲染器随内置界面一起发布：**Document AI** 模板使用其打包代码中的 **PDF.js** 来渲染 PDF。这是一个具体的先例，证明大型库可以在界面中运行，包括那些内部编译或将工作卸载到 Web Worker 的库。

## 故障排除

| 症状 | 可能的原因 | 解决方法 |
|---|---|---|
| 对我的服务的 `fetch()` 被阻止 | 该主机不在 **API 来源（API origins）** 中，或被错误地列在 **外部脚本（external scripts）** 下。 | 在 **API 来源（API origins）**（方式 1）下添加精确来源。 |
| 我的 CDN `<script>` 无法加载，但我已将主机添加到 **API 来源（API origins）** | **API 来源（API origins）** 管理的是数据请求，而非脚本加载。 | 在 **高级：外部脚本（Advanced: external scripts）** 下添加主机并启用开关（方式 2）。 |
| "界面不能使用包" | 将"不能 import"规则误解为禁止所有第三方代码。 | 您不能 `import` npm 包，但可以将其打包进来（方式 3）或从允许列表中的 CDN 加载（方式 2）。 |
| 打包的库在应用中工作但本地验证失败 | 构建依赖于顶层 `module.exports`/`require`。 | 使用 **IIFE/全局** 构建（例如 `esbuild --format=iife --global-name=…`）并引用其定义的变量。 |
| 库期望 Node API 或父级 `window` | 它不兼容浏览器/沙盒。 | 使用浏览器构建；确保任何网络调用受 **API 来源（API origins）** 的约束。 |
