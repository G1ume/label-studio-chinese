在 Label Studio Enterprise 中，您可以应用不同的指标来衡量标注员之间的一致性。

任务一致性，也称为"标注共识"或"注释共识"，表示多个标注员对同一任务进行标注时的一致程度。

一致性有助于您判断数据集的质量及其用于训练模型的就绪程度，并评估标注员和审核员的绩效。

## 查看一致性

您可以通过以下方式查看一致性：
- **数据管理器** - 显示每个任务的任务一致性以及标注员之间的一致性。参见[数据管理器中的一致性列](manage_data#Agreement-columns)。
- **数据质量仪表盘** - 显示任务一致性分布、各维度一致性、主要混淆对以及混淆矩阵。参见[数据质量仪表盘](dashboard_data_quality)。
- **成员仪表盘** - 显示成员与模型一致性矩阵。参见[成员仪表盘](dashboard_members)。

!!! note
    成员仪表盘中显示的所有一致性分数均使用**成对（Pairwise）** 方法计算。

## 整体一致性与各控件标签一致性

一致性在两个层面进行计算：

* 各控件标签一致性（也称为"问题级一致性"）
* 整体一致性

![截图](/images/review/agreement-annotated.png)


### 各控件标签一致性

控件标签是用于标注数据的标签。对象标签是用于标识待标注数据的标签，例如 `Image`、`Text` 和 `Audio`。

例如，如果您的标注配置涉及使用 `RectangleLabels`、`Choices` 和 `Rating` 对图像进行标注，那么您将拥有三个控件标签。

一致性会针对每个控件标签单独计算，您可以为每个控件标签配置用于计算一致性的指标。参见[内置一致性指标参考](agreement_metrics)。

在数据管理器中，您可以分别查看每个控件标签的一致性分数。这使您能够了解任务的哪些部分一致性较高或较低（例如，边界框的一致性较好，但选择字段的一致性较低）。

### 整体一致性

Label Studio 将各控件标签的分数聚合为一个任务级别的分数。

默认情况下，该分数计算为所有控件标签分数的平均值。当您未按控件标签筛选时，这就是主**一致性**列中显示的内容。

您可以通过在计算一致性时设置不同控件标签的**权重**来自定义整体一致性的计算方式。

这样可以确保关键控件标签对整体一致性分数的影响大于不太重要的控件标签。参见[配置整体一致性的权重](#配置整体一致性的权重)。

## 分类控件标签与非分类控件标签

一致性计算的方式因控件标签是*分类（categorical）* 还是*非分类（non-categorical）*（也分别称为*离散*和*连续*）而有本质区别。

这一区别会影响数据提取、比较指标以及评分机制。

### 分类控件标签

分类控件标签产生离散的有限值。标注员从一组预定义的选项中选择。

示例包括：

- **Choices**（例如"小"、"中"、"大"）
- **Rating**（例如 1-5 星评分）

由于分类值是离散的，典型指标是**精确匹配（Exact Match）**——两个值要么匹配（得分 = `1.0`），要么不匹配（得分 = `0.0`）。

但是，**Rating** 或 **Number** 等标签也可以使用[**带阈值的数值差（Numeric Difference with Threshold）**](agreement_metrics#Numeric-Difference)，您可以在其中定义可容忍的数值偏差（例如，阈值为 `0` 表示只有完全相同的评分才算匹配）。

分类比较本质上产生二值分数（`0` 或 `1`）。这意味着它们可以与两种一致性方法配合使用：

- [**成对平均（Pairwise Average）**](#成对)：对所有标注员对的 0 和 1 求平均值。
- [**共识（Consensus）**](#共识)：由于分数已经是二值的，无需进行阈值转换。共识方法自然地反映了多数一致性。

参见[分类示例](#分类示例)了解如何计算分类控件标签的一致性。

### 非分类控件标签

非分类控件标签产生空间、几何或结构化数据。标注员绘制区域、高亮文本片段或定位元素。

例如：

- **RectangleLabels**（围绕对象的边界框）
- **Labels**（文本片段 / NER 标注）
- **PolygonLabels**、**EllipseLabels**、**KeyPointLabels** 等。

由于两位标注员很少绘制完全相同的区域，系统使用连续相似度指标来衡量重叠程度。例如：

- [**IoU（交并比）**](agreement_metrics#Intersection-over-Union-for-bounding-boxes)用于边界框和多边形。返回介于 `0.0`（无重叠）和 `1.0`（完全重叠）之间的浮点数
- [**文本片段重叠度（Span Overlap）**](agreement_metrics#Span-Overlap)用于文本片段。衡量两个高亮文本区域的重叠程度

参见[非分类示例](#非分类示例)了解如何计算非分类控件标签的一致性。


##### 差异总结

| 方面 | 分类标签 | 非分类标签 |
|---|---|---|
| **输出类型** | 离散值（标签、评分） | 空间/结构化数据（框、文本片段） |
| **典型指标** | 精确匹配、数值差 | IoU、文本片段重叠度 |
| **分数类型** | 二值（`0` 或 `1`） | 连续（`0.0` 到 `1.0`） |
| **成对（Pairwise）** | 直接使用；对二值分数求平均 | 直接使用；对连续分数求平均 |
| **共识（Consensus）** | 直接使用；无需阈值 | 需要用户定义阈值以先将分数二值化 |


## 方法论

您可以在**设置 > 质量 > 一致性**部分为每个项目配置使用的方法论。

<img src="/images/review/agreement-methodology.png" class="gif-border" style="max-width:600px">

您可以选择以下方法论：

* **共识（Consensus）**：共识衡量的是*"有多少比例的标注员选择了最常见的答案？"*

  ![共识示例](/images/review/consensus-categorical.png)

* **成对（Pairwise）**：成对衡量的是*"所有标注员对之间的一致性平均得分是多少？"*

  ![成对示例](/images/review/pairwise-categorical.png)

!!! info 提示
    您可以随时在方法论之间切换。

### 共识（Consensus）

共识一次性计算所有标注员之间的一致性，衡量他们趋向共同答案的程度。

<img src="/images/review/consensus-1.png" alt="截图" style="display: block; margin: 0 auto; max-width: 300px" />

有两种同样有效的方式来看待共识：

* *有多少标注员意见一致？*

以及

* *有多少标注员选择了最常见的答案？*

说明这一点最简单的方式是通过一个示例，其中每个标注员选择了不同的选项：

* 标注员 1 选择 A
* 标注员 2 选择 B
* 标注员 3 选择 C

尽管标注员之间没有相互一致，一致性仍然是 `1/3 = 33.33%`。

* *有多少标注员意见一致？*

  给定三位标注员，每个选项被 1/3 的人选择：`1/3 = 33.33%`

* *有多少标注员选择了最常见的答案？*

  在这种情况下，A、B 和 C 各被选择了一次，因此它们同样常见。

  因此 3 位标注员中有 1 位选择了最常见的答案：`1/3 = 33.33%`

如果切换到成对（Pairwise）方法论，相同的任务将得到 `0%` 的一致性分数，因为成对更关注标注员对之间的一致性程度。

#### 共识中的二值评分

共识使用二值分数衡量一致性——每对标注员要么匹配（`1`），要么不匹配（`0`）。

* 对于像 **Choices** 或 **Rating** 这样的分类标签，这种二值结果自然产生：两位标注员要么选择了相同的值，要么没有。

* 对于像边界框或文本片段这样的非分类标签，原始比较产生一个连续分数（例如，IoU 为 `0.82`）。因此对于非分类标签，您必须定义一个阈值来判断连续分数是否足够高以被视为匹配，从而使 Label Studio 能够将其转换为二值决策。

  达到或超过阈值算作匹配（`1`），低于阈值则不算（`0`）。

一旦标注被简化为 `1` 或 `0`，共识就计算整个群体整体趋同的程度。

### 成对（Pairwise）

顾名思义，成对（Pairwise）考察每一对唯一标注员之间的一致性，然后对这些一致性求平均。

<img src="/images/review/pairwise-1.png" alt="截图" style="display: block; margin: 0 auto; max-width: 300px" />

成对通过独立比较每一对唯一标注员、为每对计算得分，然后对所有得分求平均来衡量一致性。

沿用之前的示例：

* 标注员 1 选择 A
* 标注员 2 选择 B
* 标注员 3 选择 C

共识一致性分数为 `33.33%`，而成对一致性分数为 `0%`。

* 标注员 1 与标注员 2 比较（不匹配 = `0`）
* 标注员 1 与标注员 3 比较（不匹配 = `0`）
* 标注员 2 与标注员 3 比较（不匹配 = `0`）

`(0 + 0 + 0)/3 = 0`

对于分类标签，每对产生一个二值结果：匹配得分为 `1`，不匹配得分为 `0`。这些二值的平均值即为整体一致性。

对于像边界框这样的非分类标签，每对产生一个连续分数（例如，IoU 为 `0.82`），这些原始分数直接求平均而无需任何阈值转换。

这意味着成对方法保留了非分类比较的全部粒度，奖励部分重叠而不是将其简化为全有或全无。

!!! info 提示
    对于使用共识方法论的非分类标签，您必须使用精确匹配或带有阈值的连续指标。对于成对方法，您可以使用精确匹配、不带阈值的连续指标或带阈值的连续指标。

### 共识与成对方法一览

| | **成对（Pairwise）** | **共识（Consensus）** |
|---|---|---|
| **工作原理** | 比较每一对唯一标注员，为每对打分，并对所有对的分数求平均 | 使用二值匹配/不匹配来衡量整个群体趋向共同答案的程度 |
| **使用的分数类型** | 直接使用原始分数（分类为二值，非分类为连续） | 始终要求二值分数（匹配或不匹配） |
| **需要阈值？** | 否——直接使用原始分数 | 仅非分类标签需要；分类标签已经是二值 |
| **部分得分** | 是——边界框重叠度为 0.6 则对平均值贡献 0.6 | 否——重叠要么高于阈值（匹配），要么低于阈值（不匹配） |
| **对离群值的敏感度** | 高——一个不一致的标注员会产生多个低分对，拉低平均值 | 低——一个不一致的标注员会被多数票否决 |
| **3 位标注员，2 位一致（分类）** | 33%（只有 3 对中的 1 对匹配） | 66%（识别多数一致性） |
| **3 位标注员，全部一致** | 100% | 100% |
| **3 位标注员，无人一致** | 0% | 33%（3 位中的 1 位选择了最常见的答案） |
| **最适合** | 每个任务有 2 位标注员的项目，或需要细粒度连续分数的项目 | 每个任务有 3 位以上标注员的项目，或多数一致性最为重要的项目 |

#### 何时选择成对与共识

用最简单的话来说：

* 如果您更关注标注员，成对是最佳选择。
* 如果您更关注大多数标注员是否同意某个特定答案，共识是最佳选择。

##### 成对（Pairwise）

**成对**告诉您标注员之间整体的一致程度。

* 最适合于您关心评估标注员、想了解标注人员池中的不一致/碎片化情况以及发现任务和/或说明中的歧义。

* 对离群值更敏感，这可能是需要的（单个不一致的标注员可以显著降低分数）

* 成对不需要您为非分类控件标签（例如 `RectangleLabels` 和 `TextArea`）定义阈值，因此在这些情况下设置可能更简单。

##### 共识（Consensus）

**共识**告诉您任务在多大程度上趋向于一个答案。

* 更好地反映多数一致性，对大多数用户来说更直观。

* 对离群值更稳健（单个不一致的标注员影响更小）。

* 共识度量是标签稳定性和任务收敛性的良好代理指标。

* 需要为非分类控件标签设置阈值。阈值是您定义什么是"足够接近"的方式。参见[非分类示例](#非分类示例)了解使用阈值的共识计算示例。

#### 分类示例

[分类控件标签](#分类控件标签)是具有固定选项集的控件标签。例如，具有选项"Opossum"、"Cat"、"Hamster"的控件标签。


<div class="code-tabs">

假设有 3 位标注员在 3 个不同选项"A"、"B"、"C"之间选择。

![成对示例](/images/review/pairwise-categorical-0.png)

如果三位标注员选择了不同的选项，成对得分为 `0`：

* 标注员 1 与标注员 2 比较（不匹配 = `0`）
* 标注员 1 与标注员 3 比较（不匹配 = `0`）
* 标注员 2 与标注员 3 比较（不匹配 = `0`）

`(0 + 0 + 0)/3 = 0`

![成对示例](/images/review/pairwise-categorical-1.png)

如果标注员 2 更改选择以与标注员 1 一致，一致性将变为 `33.33%`：

* 标注员 1 与标注员 2 比较（匹配 = `1`）
* 标注员 1 与标注员 3 比较（不匹配 = `0`）
* 标注员 2 与标注员 3 比较（不匹配 = `0`）

`(1 + 0 + 0)/3 = .33`

![成对示例](/images/review/pairwise-categorical-2.png)

如果标注员 3 更改选择以与标注员 1 和标注员 2 一致，一致性将变为 `100%`：

* 标注员 1 与标注员 2 比较（匹配 = `1`）
* 标注员 1 与标注员 3 比较（匹配 = `1`）
* 标注员 2 与标注员 3 比较（匹配 = `1`）

`(1 + 1 + 1)/3 = 1`

正如您所见，成对方法可能不如共识方法直观（例如，当标注员 3 更改选择时从 33.33% 变为 100%），但它对离群值更敏感。

假设有 3 位标注员在 3 个不同选项"A"、"B"、"C"之间选择。

![共识示例](/images/review/consensus-categorical-0.png)

如果三位标注员选择了不同的选项，共识得分为 `33.33%`：

* 标注员 1 选择"A"
* 标注员 2 选择"B"
* 标注员 3 选择"C"

在共识方法中，我们关注最常见的答案。在本例中，`A`、`B` 和 `C` 各被选择了一次，因此它们同样常见。

因此 3 位标注员中有 1 位选择了最常见的答案（`1/3 = .33`）。

* 他们的选项值是什么并不重要，重要的是有 3 个选项且标注员之间没有重叠的选择。
* 在这种情况下，任何一个选项都可以成为"最常见的答案"，因为它们同样常见（每个都被选择了一次）。

![共识示例](/images/review/consensus-categorical-1.png)

如果标注员 2 更改选择以与标注员 1 一致，一致性将增加到 `66.67%`：

* 标注员 1 选择"A"
* 标注员 2 选择"A"
* 标注员 3 选择"C"

在这种情况下，`A` 被选择了两次，`C` 被选择了一次。

因此 3 位标注员中有 2 位选择了最常见的答案（`2/3 = .66`）。

![共识示例](/images/review/consensus-categorical-2.png)

如果标注员 3 更改选择以与标注员 1 和标注员 2 一致，一致性将增加到 `100%`。

3 位标注员全部选择了最常见的答案（`3/3 = 1.0`）。

#### 非分类示例

[非分类控件标签](#非分类控件标签)是具有连续值的控件标签，不像"匹配"或"不匹配"那样容易量化。例如，**RectangleLabels**、**PolygonLabels** 和 **Labels**。

##### 边界框

当您用边界框标注图像时，可以使用**精确匹配（Exact Match）**、**交并比（IoU）** 或**带阈值的交并比（IoU (Threshold)）** 指标。

在本示例中，我们将考察**交并比（IoU）** 和**带阈值的交并比（IoU (Threshold)）**。

交并比（Intersection over Union，简称 IoU）是描述两个边界框相似程度的一种方式。

其思想是：

- **交集（Intersection）**：两个框共享的区域
- **并集（Union）**：两个框共同覆盖的总区域

有关 IoU 如何计算的更多信息，请参见[交并比（IoU）](agreement_metrics#Intersection-over-Union-for-bounding-boxes)。

有关阈值的更多信息，请观看以下视频：

假设有 3 位标注员使用 **RectangleLabels** 绘制框。您正在使用**交并比（IoU）** 指标来计算一致性。

![成对示例](/images/review/pairwise-non-categorical-bbox.png)

如果三位标注员在图像完全不同区域绘制框，没有重叠，成对得分为 `0%`：

* 标注员 1 与标注员 2 比较（无重叠，IoU = `0`）
* 标注员 1 与标注员 3 比较（无重叠，IoU = `0`）
* 标注员 2 与标注员 3 比较（无重叠，IoU = `0`）

`(0 + 0 + 0) / 3 = 0`

现在标注员调整他们的框，使它们之间有一些重叠。在这种情况下，一致性为 `40.67%`：

- 标注员 1 与标注员 2 比较（IoU = `.53`）
- 标注员 1 与标注员 3 比较（IoU = `.24`）
- 标注员 2 与标注员 3 比较（IoU = `.45`）

`(.53 + .24 + .45) / 3 = 40.67%`

<div data-name="共识（Consensus）">

假设有 3 位标注员使用 **RectangleLabels** 绘制框。

然而，共识方法要求二值（`0` 或 `1`）分数。因此这次，您使用**带阈值的交并比（IoU (Threshold)）** 指标来计算一致性。

这与成对示例中使用的**交并比**指标相同，只是应用了一个阈值。阈值是必需的，用于确定什么算作匹配（`1`），什么不算匹配（`0`）。

假设您将阈值设置为 `50%`：任何 IoU >= 0.50 的对算作匹配（`1`），低于该值的对不算匹配（`0`）。

![共识示例](/images/review/consensus-non-categorical-bbox.png)

您有以下原始 IoU 分数：

- 标注员 1 与标注员 2 比较（IoU = `.53`）
- 标注员 1 与标注员 3 比较（IoU = `.24`）
- 标注员 2 与标注员 3 比较（IoU = `.45`）

**使用阈值（50%）进行二值化：**

- 标注员 1 与标注员 2 比较：`.53` >= `.50` → 匹配 = 1
- 标注员 1 与标注员 3 比较：`.24` <= `.50` → 不匹配 = 0
- 标注员 2 与标注员 3 比较：`.45` <= `.50` → 不匹配 = 0

标注员 1 和标注员 2 一致，共识分数为 `2/3 = .66`。

**更强的 IoU 一致性**

有些情况下，一致性不仅限于 2 位标注员一致，但也没有到三位全部一致的程度。

例如，在下图中：

![负鼠边界框截图](/images/review/agreement-bbox-opossum.png)

* 标注员 1 和标注员 2 有较强的重叠
* 标注员 2 和标注员 3 有较强的重叠
* 标注员 1 和标注员 3 有较弱的重叠

在这些情况下，一致性会更高以反映存在比简单的 2/3 共识更强的一致性。（在上述示例中，一致性分数为 `80.47%`。）

  </div>
</div>

##### 文本片段

当您标注文本片段时，可以使用**精确匹配（Exact Match）**、**文本片段重叠度（Span Overlap）** 或**带阈值的文本片段重叠度（Span Overlap (Threshold)）** 指标。

在本示例中，我们将考察**文本片段重叠度**和**带阈值的文本片段重叠度**。

文本片段重叠度衡量标注员高亮区域的重合程度。有关其计算方式的更多信息，请参见[文本片段重叠度](agreement_metrics#Span-Overlap)。

## 其他一致性设置

选择方法论后，您可以在**设置 > 质量 > 一致性**下配置一致性的其他设置。

### 内置指标与自定义指标

在**内置指标与自定义**下，您可以选择是自定义自己的一致性指标还是使用内置指标。

* **内置一致性指标** - 如果您选择**内置指标**，您将看到[内置指标参考](agreement_metrics)中列出的内置指标。

* **自定义一致性指标** - 如果您选择**自定义指标**，您将能够通过在文本框中编写代码来创建自己的自定义一致性指标。参见[为 Label Studio 添加自定义一致性指标](custom_metric)。

### 配置整体一致性的权重

整体一致性是所有控件标签一致性分数的平均值。它显示在数据管理器的主**一致性**列中。

在**设置 > 质量 > 一致性 > 整体一致性**下，您可以通过在计算一致性时设置不同控件标签的**权重**来自定义整体一致性的计算方式。

这样可以确保关键控件标签对整体一致性分数的影响大于不太重要的控件标签。

<img src="/images/review/agreement-overall.png" class="gif-border" style="max-width:600px">

例如，如果您的项目具有以下控件标签和权重：
- RectangleLabels：1.0
- Choices：0.3
- Rating：0.2

以及某个任务的以下各控件标签一致性分数：
- RectangleLabels：83%
- Choices：33%
- Rating：33%

那么整体一致性计算如下：

`(1.0 * 83% + 0.3 * 33% + 0.2 * 33%) / (1.0 + 0.3 + 0.2) = 60.67%`


### 为每个控件标签配置一致性

在**设置 > 质量 > 一致性 > 一致性列**下，您可以为每个控件标签自定义一致性的计算方式。

<img src="/images/review/agreement-column-settings.png" class="gif-border" style="max-width:600px">

您的选项取决于您选择的一致性方法论以及您正在配置的控件标签类型。

有关每个控件标签可用的不同指标的信息，请参见[内置指标参考](agreement_metrics)。
